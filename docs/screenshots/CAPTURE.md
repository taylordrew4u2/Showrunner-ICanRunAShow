# Screenshots

Everything in this folder is generated by `npm run screenshots`
([`scripts/capture-screenshots.mjs`](../../scripts/capture-screenshots.mjs)) and
rendered in the main README's **Screenshots** section. Nothing here is captured
by hand, so regenerating after a UI change is a single command rather than an
afternoon.

## Regenerating

The reliable way, and the one the committed images were made with — no account,
no database, no API keys. It runs against a local production build with the same
in-memory backend the end-to-end suite uses:

```bash
npm run build
npx vite preview --port 4173 &
MOCK_API=1 APP_URL=http://localhost:4173 npm run screenshots
```

Against the live app instead, with a throwaway demo account:

```bash
DEMO_USER=demo DEMO_PASS=… APP_URL=https://icanrunashow.com npm run screenshots
```

Never point `DEMO_USER` / `DEMO_PASS` at a real account — the seed step assumes
it may populate an empty workspace.

### Environment

| Variable | Default | Purpose |
| --- | --- | --- |
| `APP_URL` | `https://icanrunashow.com` | Target app |
| `MOCK_API` | unset | `1` to use the in-memory backend — no account or database |
| `OUT_DIR` | `docs/screenshots` | Where the PNGs land |
| `HEADLESS` | `true` | `false` to watch it run |
| `PW_CHROMIUM_PATH` | unset | A Chromium already on disk, for sandboxes that cannot download Playwright's pinned build |

## What gets captured

Everything is shot at 430×932 with `deviceScaleFactor: 2`, so the images are @2x
and the app is in the phone layout it is designed around.

| File | Screen |
| --- | --- |
| `shows.png` | The shows dashboard |
| `show-detail.png` | A show's page — summary tiles and the section accordion |
| `schedule.png` | The run-of-show builder |
| `performer-profile.png` | A performer's profile |
| `run-show.png` | Full-screen live mode |
| `rolodex.png` | The Rolodex, with its show-type-aware wording |
| `settings.png` | Settings — theme, brand, and the folded workspace details |
| `more.png` | The More hub |
| `contracts.png` | A contract's status list: one signed, one waiting |
| `signing-receipt.png` | What the signer sees once they have signed |
| `stage-remote.png` | Settings — a paired stage remote, and the storage sweep |

## Notes

- **`signing-receipt.png` is an element shot, not a full page.** Headless
  Chromium does not reliably paint a PDF inside an `<object>`, and a blank
  document pane above the receipt would say something untrue about the app.
- **There is no animated demo.** The README's hero used to be a GIF, dropped
  when it went stale — it still showed a gold accent and a navigation bar the
  app no longer has. Re-recording one is a genuine improvement; a screenshot of
  an app that no longer exists is not.
- **There is no viewer-link shot.** Capturing it needs the show's viewer token,
  which only exists once the live screen has published, and automating that was
  not worth the coupling. Worth adding if the flow settles.
